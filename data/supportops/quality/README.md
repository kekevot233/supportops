# 完整性开发数据与冻结保留集

本目录是评测材料，不是默认知识库摄取目录，不包含真实企业资料或凭据。

- `failure_review.json`：对原 RET-08/RET-19 的 AI 辅助来源/代码复核，不是独立人工裁决；
  仍保留原严格判分失败及 30/32，不把复核后的核心答案有依据改写成原测试通过。
- `development.json`：两个明确提问边界的开发案例 RET-81/RET-82，允许用于提示词开发。
  与原 `evaluation/answers.json`、`cases.json` 分开，不改变旧真实调用的摘要绑定。
- `holdout/corpus/`：三份新编的虚构支持流程材料，明确不是 SupportOps 已实现或已部署的能力。
  采用独立 manifest 和文档 ID，不混入原 10 份种子资料；`source_refs` 指向本说明。
- `holdout/cases.json`：12 题，6 个多条件事实题、3 个拒答题、3 个伪造指令污染题。
  题集/标注不摄取进索引，不作为模型提示词示例，污染只存在于逐题内存副本。
- `holdout.freeze.json`：候选 `complete-evidence-v2` 提示词定稿后创建，固定数据、语料和提示词
  摘要；加载器另固定 manifest 的规范化 JSON 摘要，修改文件后仅更新 manifest 不能静默通过。

本资料由同一 AI 辅助实现者整理，不是领域专家独立标注，也不保证作者未见过题目。
“保留”表示不用于本次调优、按独立语料和冻结协议留作下一步验证，不代表安全隔离或严格盲测。
所有数据均可由有文件访问权限的人阅读，摘要是完整性检查，不是保密或数字签名。

当前只验证结构、标注是否来自原文、污染隔离与冻结摘要，**没有运行保留集的模型回答或评分**。
测试中的开封只模拟执行失败并写入临时目录，没有生成真正保留题答案。
未来一旦看过其结果再调优，该版本应被视为回归集，不再作为新的独立质量证明。
