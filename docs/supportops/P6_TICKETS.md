# P6a：工单助手最小闭环

日期：2026-10-19。已实现服务、API 和本机网页；本轮只做临时库/Fake 与模拟浏览器验证，
没有读取真实配置、发送付费请求或改动用户已有业务库。不是外部工单平台或生产发布。

## 能做什么

```text
提交问题（待处理） → 生成引用建议（仍待处理） → 人工核对采纳（处理中） → 人工记录结果（已解决）
              └→ 无资料或不采用建议 → 填写原因、人工接管（处理中） ────────────────┘
```

- 工单包含标题、描述、人工选择的分类/优先级、状态、修订号和时间线，仅本人可见。
  reader 可以提交自己的支持问题，但仍不能修改知识文档。管理员不能查看别人的私有工单。
- “生成引用建议”复用现有 ChatService → AnswerEngine → 检索/上下文/预算/引用校验，不另建
  一套 LLM 协议。查询只用工单标题与描述，避免通用工作流提示稀释召回相关性。
  每个建议创建独立私有会话，最多一次 Chat，绑定原回答、原文引用与运行 ID。
- 建议仍是抽取式原文，不是已经验证可执行的诊断方案。不会自动分类、判断紧急程度、执行
  命令、处理外部工单、采纳建议或关闭工单。分类与优先级的来源明确为 user_selected。
- 只有 answered 且来源仍为 current 的建议可由用户确认采纳；资料不足、更新或删除后不能
  当成当前有效建议采纳。资料删除后的建议正文复用问答层隐藏逻辑，不复制模型正文快照。
- 无依据时可以显式填写理由“人工接管”，不伪造已采纳的建议；之后人工追加记录并确认解决。
  状态变化只是本系统记录，不等于外部系统已经修复。
- 工单、建议版本和事件记录持久化；状态修改与审计同事务。解决记录不自动写入知识库。

## 使用

停止旧的本机服务，建议在停止后备份业务库，再用原命令重启。例如默认 Fake：

```powershell
cd D:\code\Hello-agent
D:\conda-envs\helloagent\python.exe -m supportops serve --enable-demo --profile reader --port 8765 --open-browser
```

已有资料按原样保留；新副本应先按 README 初始化并导入公开种子文档。进入左侧“工单助手”：

1. 填写标题、现象及已尝试步骤，人工选择分类和优先级，创建工单。这一步不调用模型。
2. 点击“生成引用建议”，查看建议引用与运行详情。Fake 仅用于演示，不能据其摘录判断方案正确。
3. 核对来源后点击“人工确认并开始处理”；也可选择“人工接管”并填写原因。
4. 实际处理后追加记录，填写解决结果，再明确确认“记录结果并标记解决”。

真实模式继续使用 [P5e 的 serve-live 命令](P5_LIVE_WORKBENCH.md)。生成建议前会显示同样的
外发确认，问题和公开证据只经既有隔离 worker 发往 DeepSeek，继续受原累计账本与该启动
会话的金额/次数限制；不重新授予预算。仅“生成建议”可能付费，其余工单动作不调用模型。
工单内容也必须是可发送给供应商的公开内容，不接企业/个人敏感资料。本轮未真实调用。

## API

所有路径前缀为 `/api/workspaces/{workspace}/tickets`，身份、空间成员关系与工单所有者由服务端校验。

| 方法与后缀 | 行为 |
| --- | --- |
| GET / POST 根路径 | 列出本人工单 / 幂等创建 |
| GET /{ticket} | 工单、建议关联与处理时间线 |
| POST /{ticket}/suggestions | 显式生成新建议；同键只返回状态，不重调模型 |
| POST /{ticket}/accept | 指定 suggestion_id，确认采纳当前有效证据并开始处理 |
| POST /{ticket}/start | 填写 content 原因，明确人工接管，不采纳模型结果 |
| POST /{ticket}/note | 追加实际处理记录 content |
| POST /{ticket}/resolve | 填写解决记录 content，人工确认已解决 |
| POST /{ticket}/suggestions/{suggestion}/reconcile | 空对象请求；只对账已有运行，不重调模型 |

创建字段为 title、description（最多1600字符）、category、priority、idempotency_key。
suggestions/accept/start/note/resolve 请求都携带 expected_revision 与 idempotency_key；
accept/start/resolve 还要求严格布尔 `confirm: true`。拒绝额外身份、状态、执行命令或模型字段。
同键不同内容、过期修订号及错误状态返回409；越权与不存在保持一致的404。每人每空间最多
100张工单，每张最多10个建议版本，修订号到200后停止新增修改；列表不是无限分页服务。

## 失败与中断

建议开始前先落盘 generating 及独立会话；失败保留错误/运行标识。同键再次请求只返回已有
状态，刷新页面和核对中断状态都不会触发模型。正常中断没有完成结果时，300秒后可以显式
核对并标记失败；若回答已经提交而工单关联未完成，可只关联那次已提交的 ticket-suggestion
回答，不采纳其他问答，也不重放模型。新建建议仍需用户显式操作与授权，真实预算的停止状态
不会由工单恢复入口清除。没有后台自动重试或恰好一次的外部副作用保证。
